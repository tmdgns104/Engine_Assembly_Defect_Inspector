# TASK-024 — 부품별 결과·처리 과정 표시 및 재시험 복구 UI

## 요청과 범위
- `/line`의 저장 결과에 네 부품의 존재/조립 상태, 실제 원본→몸체 정렬→crop→분류 과정을 표시한다. 상세는 선택한 검사 ID로 한 번 읽고, 빠른 미리보기 루프를 유지한다.
- 촬영 없는 ERROR, 정렬 실패, 분류 미실행을 결품/오조립으로 오인하지 않도록 구분한다. 판정·모델·정렬 알고리즘은 변경하지 않는다.
- 정상 자동검사는 그대로 PLC가 주도한다. 예외적인 재시험 버튼은 기존 `close_previous_product_context()`를 사용한다. 현재 STOP/무출력/유휴, 원장 무결성, 미완료 없음 및 실제 제품 정리 확인을 재검증한다.
- 복구는 별도의 유지보수 종료 기록이며 AI CLEAR/새 권한/과거 결과 재송신이 아니다. 통신·카메라·저장 오류와 실제 미완료 검사는 원인을 표시하고 차단한다.
- 사용자 후속 지시: Reset의 코드 생성·입력·검증과 담당자/사유/체크박스를 제거한다. 현장 정지·모형 정리 확인 버튼과 PLC·원장 보호를 유지한다. 정확한 same-origin Reset 이외 일반 POST는 허용하지 않는다.
- 사용자 현장 STOP 확인 후 백업·소스/SHA 검증·서비스 전환을 수행한다. 새 START·제품 복구 실행·결과 송신은 이번 UI 적용 과정에서 하지 않는다.

## 검증
- 실제 정렬 실패/촬영 없음 구조와 합성 결품·오조립·상충/미실행 구조로 UI 계약 검증.
- 복구 조회는 무변경; 인증·STOP·출력·작업·기존 기록·변경 경쟁 조건 검증. 과거 기록 보존과 새 정상 요청 회귀 재사용.
- 미리보기 중복/적체/상태 조회 독립성 회귀; 실제 Jetson 네이티브 및 화면 확인.
- 모델·PLC·통신·gold 특징점 변경 없음. gold 추가 실험은 개선 근거 없어 미채택.

# V0-T04 학습 기록

## 무엇을 했는가

Windows PC에서 단일 이미지 수집 CLI, PNG/JSONL 저장, 세션 검증 도구와 81장 Pilot 계획을 만들었다. 실제 장비 없는 sample 경로와 metadata·저장 실패 테스트를 수행했다. 이후 사용자가 기존 두 스크립트를 SCP로 전달하고 Jetson 실제 HCAM0에서 CAMERA_SMOKE 3장을 저장·검증했다. FINALIZE는 사용자가 제공한 결과를 Windows에서 문서화하는 작업이며 Jetson을 다시 실행하지 않았다.

## 왜 했는가

이미지를 모은 뒤에 촬영 조건을 추측하지 않도록 처음부터 Session/Episode를 남기기 위해서다. Session은 한 촬영 작업 단위이고 Episode는 한 번 실제로 물체를 배치한 상태다. 같은 배치의 여러 사진은 서로 매우 비슷할 수 있으므로 독립적인 샘플로 취급하면 안 된다.

## 무엇을 관찰했는가

기존 Contract 테스트 19개와 Capture 테스트 21개, 총 40개가 통과했다. Windows synthetic sample 3장은 실제 PNG로 저장·재로드됐고 JSONL의 ID·크기·hash와 연결됐다. 같은 capture_id 덮어쓰기, Episode 안의 시나리오/입력 조건 변경, orphan 파일, 불완전 manifest가 거부됐다. 의도적으로 손상시킨 PNG는 byte hash가 맞더라도 decoder에서 거부되는 것을 확인했다.

초기 T04 구현 검증에서 T02/T03 관련 22개 파일 해시와 설치 패키지 42개의 이름·버전은 유지됐다. 이번 FINALIZE는 코드·가상환경을 변경하지 않는다. Windows sample 성공과 사용자 실행 Jetson 증거를 별도로 기록했다.

사용자의 최종 하드웨어 결과는 jetson-07, Python 3.10.12, OpenCV 4.8.0, HCAM0의 /dev/video0, YUYV 640×480, 설정 22 FPS다. V4L2는 30프레임 수신 후 exit 0, OpenCV는 V4L2 backend로 opened=True 및 5/5 읽기에 성공했다. 실제 PNG 3장은 metadata·크기·SHA256·OpenCV 재로드 검증을 통과했다. 이는 사용자가 실행해 제공한 결과이며 Codex가 원격에서 재실행한 결과는 아니다.

사용자는 중간 카메라 실패의 원인이 USB Camera 미연결이었다고 정정했다. 카메라가 연결되지 않으면 그 카메라의 /dev/video* 노드가 사라질 수 있다. 다른 카메라 노드가 남아 있을 수도 있으므로 번호만 찾지 말고 장치 이름과 Video Capture 기능을 확인한다. 이전에는 /dev/video2로 스트리밍이 성공했고, 최종 재연결 후에는 /dev/video0이었다. 중간 실패와 앞선 성공 기록을 혼동하지 않는다.

## 결과가 의미하는 것

수집 시 metadata를 남기면 T06에서 같은 Episode를 서로 다른 train/val/test로 나누는 일을 피할 수 있다. burst frame만 많이 모으면 같은 배경과 거의 같은 물체 모습이 양쪽에 들어가 성능이 좋아 보이는 Data Leakage가 발생할 수 있다. 실제 재배치가 있었는지는 사람이 기록해야 하며 ID만 달리한다고 독립 데이터가 되지 않는다.

V4L2/OpenCV 오류가 나면 backend를 고치기 전에 물리 연결과 현재 장치 enumeration부터 확인한다. /dev/videoX 번호는 재연결 후 달라질 수 있으므로 영구 장치 identity가 아니다. **장치 존재 → stream → OpenCV read → 실제 저장 → reload/hash**는 서로 다른 검증 단계다. 설정 22 FPS와 이전 스트림 진행 표시의 4.88·13.37 FPS도 구분하며 지속 처리 성능을 증명했다고 하지 않는다.

파일 존재·크기·hash와 이미지 해석 성공도 다른 검사다. 두 파일에 걸친 저장은 완전한 transaction이 아니므로 중단 흔적을 숨기거나 덮어쓰지 않고 보존해야 한다. T04의 계획·도구·metadata·하드웨어 경로는 DONE / VERIFIED지만 CAMERA_SMOKE 성공은 Dataset 품질이나 모델 정확도 성공이 아니다. 정식 Pilot은 **0/81장**이며 smoke 3장은 포함하지 않는다. 다음 HUMAN-CAPTURE-001에서 사용자가 물체를 선택·배치하고 S001 NORMAL과 MISSING_A를 한 Episode씩 촬영·검토한다. Labeling·split·training은 수행하지 않았으며 재학습도 필요하지 않다.

## V1에서 어떻게 재사용하는가

V1에서는 실제 엔진 Dataset과 클래스 정의를 별도로 승인한 뒤 적용하되, 촬영 세션·실제 배치·개별 이미지의 식별과 metadata/hash/reload 검증 절차를 재사용한다. Proxy 물체명이나 촬영 조건을 엔진 부품·tolerance로 확정하지 않는다. 이번 Capture Tool은 수집 도구이며 Production Camera Adapter와 분리되어 있다.

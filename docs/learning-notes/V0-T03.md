# V0-T03 학습 기록

## 무엇을 했는가

Windows PC에서 CameraFrame, DetectionResult, 검사 요청·결과 등 Runtime이 함께 사용할 데이터 형식과 Camera/Detector 인터페이스를 만들었다. Python 표준 라이브러리로 구현하고 테스트 안의 작은 dummy 객체로 연결을 확인했다. 실제 카메라·모델·Jetson은 실행하지 않았다.

## 왜 했는가

계약은 프로그램 부품끼리 주고받을 약속이다. 예를 들어 어떤 Detector를 쓰더라도 `detect(frame)`은 같은 DetectionResult를 돌려준다. 이 약속이 있으면 YOLO → ONNX → TensorRT 또는 ReplayCamera → V4L2Camera로 바뀔 때 나머지 프로그램을 다시 만들 필요가 줄어든다.

Protocol은 같은 메서드를 갖춘 객체를 사용할 수 있게 하는 인터페이스다. 공통 부모 클래스에서 동작을 물려받을 필요가 없어 이번에는 ABC보다 간단했다. 다만 메서드가 있다는 사실만으로 올바른 결과까지 보장하지 않으므로 테스트에서 직접 호출했다.

## 무엇을 관찰했는가

계약 테스트 19개가 통과했다. 뒤집힌 box, 범위를 벗어난 confidence, NaN, timezone 없는 시간이 거부됐다. JSON에 넣을 수 없는 image 객체를 CameraFrame에 두어도 metadata만 따로 꺼내면 JSON으로 변환할 수 있었다. 외부 패키지를 제외한 Python에서도 계약 import와 직렬화가 동작했다.

바뀐 것은 공통 타입·인터페이스·테스트와 설명 문서다. T02의 학습 모델이나 GPU 환경을 바꿀 이유가 없으며, 이번은 계약 작업이므로 재학습도 필요 없다.

## 결과가 의미하는 것

Camera와 Detector 사이의 데이터 약속을 실제 backend보다 먼저 검사할 수 있게 됐다. image payload는 메모리 안에서 처리하고 API나 Journal에는 metadata와 저장 파일 reference를 전달한다. 이미지 buffer 형식과 수명은 나중에 실제 Adapter끼리 맞춰야 한다.

`검출 0개`는 곧바로 `물리적 부품 없음`을 뜻하지 않는다. 잘 보이는 상태에서 필요한 객체가 없으면 FAIL이 가능하지만, 흐리거나 시야가 부족하면 REVIEW가 필요할 수 있다. 장치·추론·저장 실패는 ERROR다. PASS에 필요한 실제 근거와 저장 성공을 판정하는 코드는 T12/T13에서 만든다.

## V1에서 어떻게 재사용하는가

V1에서 실제 엔진 Dataset·클래스·모델·Recipe를 교체해도 공통 CameraFrame과 DetectionResult를 유지한다. 상위 코드는 특정 ML framework 결과를 해석하지 않아도 된다. V2의 실제 PLC도 manual 버튼과 같은 InspectionRequest를 생성하고 request_id로 결과를 연결한다.

필드와 책임의 정확한 정의는 [공통 계약](../contracts.md), 실행 결과는 [검증 기록](../verification/V0-T03.txt)에 남겼다.

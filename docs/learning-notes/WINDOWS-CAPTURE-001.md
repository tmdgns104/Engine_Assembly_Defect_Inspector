# WINDOWS-CAPTURE-001 학습 기록

## 무엇을 했는가
Windows에서 제품 설정을 선택하고 실시간 화면의 사진을 한 장씩 저장하는 창을 만들었다.
기존 저장/검증 함수를 연결하고 이어폰 표시 이름은 별도 설정으로 추가했다.

## 왜 했는가
사람이 배치한 상태를 정확한 정답으로 기록하고 엔진 도착 후에도 제품 설정만 바꾸어 재사용하기 위해서다.
미리보기와 저장이 한 입력 경로를 공유하며 카메라를 두 번 열지 않는다.

## 무엇을 관찰했는가
기존56개 테스트를 보존하고 모의 입력으로 연결·읽기·stale·중복·저장 실패를 검사했다. 추가36개 포함 전체92개가 통과했다.
실제 Tk 창에서 배치/수량이 가려지는 문제를 발견해 스크롤과 고정 preview 영역으로 보완했다.
카메라는 별도 프로세스, 저장/검증은 작업 스레드, 화면 갱신은 Tk 스레드가 맡는다.

## 결과가 의미하는 것
파일 존재만으로 저장 성공을 표시하지 않는다. 기록 연결과 reload/크기/hash까지 확인해야 성공이다.
Session은 같은 촬영 조건의 묶음, Episode는 한 번 실제 배치한 상태다. 같은 배치의 여러 사진은 독립 배치가 아니다.
scenario는 촬영자의 정답이며 AI 판정이 아니다. 실물 L/R도 영상 좌우만으로 정하지 않는다.

## V1에서 어떻게 재사용하는가
새 엔진 설정과 표시 이름을 만들고 같은 입력·화면·저장·검증 흐름을 쓴다. Runtime 모델/Recipe는 별도다.
수집용 objects_removed로 정상/불량을 결정하지 않는다. 합성 테스트는 실기기·Dataset 품질·엔진 검사 검증을 대체하지 않는다.
이번 학습/재학습은 없다.

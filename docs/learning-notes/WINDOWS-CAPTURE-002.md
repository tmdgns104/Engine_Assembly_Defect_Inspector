# WINDOWS-CAPTURE-002 학습 기록

## 무엇을 했는가

기존 Windows 촬영 창에 제품별 안내를 추가했다. 조건 선택 → 실제 배치 준비 → 한 장 저장 → 사람의 원본 검토 → 다음 상태 순서다.
기준 조건, 물체 위치/방향 변화, 조명 변화의 지시를 제품 JSON에 두고 공통 저장/검증기를 재사용했다.

## 왜 했는가

한 상태만 어둡게 찍거나 다른 각도로 찍으면 정답과 촬영 조건이 뒤섞인다.
카메라는 고정하고, 실제 사용에서 허용하는 물체 위치/방향·조명을 바꿀 때 각 조건에서 모든 상태를 확인하도록 돕는다.
설정 기반 안내는 촬영 절차를 일관되게 만들지만 사람이 실제 지시를 따랐는지 자동 확인하지 않는다.

## 무엇을 관찰했는가

모의 카메라에서 준비 이전 프레임, 중복 저장, 검토 전 다음 단계 이동을 차단했다.
사진 저장 후 앱이 중단된 상황은 manifest의 검증된 사진을 읽어 검토 대기로 복원했다.
재촬영은 이전 PNG를 지우지 않고 사람의 거절 사유를 별도 JSONL에 남긴다. 저장 수량과 사람이 승인한 단계 수는 다르다.
반복 Tk 창 테스트에서는 이전 창 객체가 저장 스레드의 GC에서 정리되는 오류를 발견했다.
테스트 종료 시 작업 스레드 종료를 기다리고 Tk 소유 스레드에서 객체를 정리하도록 고쳤으며 콜백 오류도 테스트 실패로 감지한다.

## 결과가 의미하는 것

촬영 절차·파일 무결성 검증과 데이터 품질/학습 성능은 별개다. 상태별 한 장은 작은 확인 라운드일 뿐 충분한 학습 데이터가 아니다.
조건 변경은 새 session, 실제 재배치/상태 변경은 episode로 보존해야 이후 묶음 기반 분할을 할 수 있다.
이번에는 추가 실물 사진을 자동 촬영하지 않았고, 조명·각도에 따른 모델 성능 실험도 하지 않았다.

## V1에서 어떻게 재사용하는가

실제 엔진이 도착하면 제품 프로필의 부품/상태와 안내 문구·허용 촬영 조건을 바꾼다.
입력·PNG 저장·manifest 검증·준비/검토/재개 흐름은 그대로 쓴다. 검토 거절 자료는 후속 데이터 검토에서 별도로 판단한다.
정확한 수집량과 재학습 필요성은 향후 검증용 독립 촬영 묶음의 오류 분석으로 결정한다.

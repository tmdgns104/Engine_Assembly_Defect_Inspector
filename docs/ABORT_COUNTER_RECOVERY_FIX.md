# 반복 사이클의 미송신 중단 복구

2026-10-15. 사용자가 승인한 기존 복구 최소 수정과 배기 결품 한 제품 시험 범위.

## 원인과 변경

OpENer의 result_count/done_count/completed_count는 프로세스 누적값이다. 기존 중단 복구는 모두 0인 첫 검사만 허용해서, 이전 완료 2건 뒤 새 요청이 송신 없이 취소된 2→2 사례도 거부했다.

`src/runtime/aborted_recovery.validate_evidence()`의 새 `REQUEST_BASELINE_V1` 증거는 Journal의 요청 토큰·수락 시각·Runtime 식별자와 C의 REQUEST_RECEIVED를 연결한다. 그때의 실제 누적값이 취소 이벤트까지 변하지 않았는지 검증한다. 정규화한 request_snapshot은 C 이벤트와 저장된 binding에서 유도한 증거이며 수신 당시 IPC 원본 패킷으로 주장하지 않는다. 과거 복구 영수증은 기존 검증 방식으로 유지한다.

`record_abort()`는 커밋 직전 재확인 콜백을 지원한다. 실제 상태가 바뀌면 이벤트와 영수증을 함께 롤백한다. `StandaloneRuntime._aborted_status()`는 검증된 ABORTED 기록이 추가되면 오래된 복구 필요 표시를 해제한다.

검사 원본·사진·결과·과거 승인 기록은 변경하지 않는다. 통합 판정을 만들지 않고 PLC 출력·검사 권한을 발행하지 않는다. 이번 최소 수정은 기존 새 Adapter 실행/정지·무출력·유휴 조건을 유지한다. 일반 Reset의 제품 문맥 종료 기능을 취소된 검사 정산 기능으로 확장한 것은 아니다.

## 검증

- 수정 전 누적 2→2 재현 및 복구 후 화면 테스트 실패 확인.
- 노트북 76개, ARM64 76개 PASS. 기존 미완료·저장공간·원본 변조·STOP 변경·중복·승인 호환성 및 새 누적값/커밋 재확인 포함.
- 실제 장치의 취소 요청은 누적 2→2, 원시 결과 저장 완료, 통합 최종판정 없음. 아직 새 현장 시험 성공을 뜻하지 않는다.
- 운영 적용과 실제 결품 한 제품 결과는 `BASIC_PART_MISSING_VERIFICATION_REPORT.md`에 별도로 기록한다.

## 복원

정지 상태에서 서비스 정상 종료 후 노트북의 직전 운영 소스·설정·Release를 복원한다. 최신 Journal/PNG/ABORTED/승인 소비 기록은 되돌리지 않는다. PLC·EDS·모델·판정·타임아웃은 변경하지 않는다.

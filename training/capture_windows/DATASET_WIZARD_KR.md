# 수집 길잡이 사용 안내

실행 파일: **`D:\OneDevice_Team_project\scripts\start_capture_windows.cmd`**

첫 버튼은 **시작 / 이어하기 → 새 수집 계획**입니다. 기존 실행 파일 그대로 사용합니다.
카메라나 사진을 외부 AI에 보내지 않습니다. 추가 설치·유료 API·학습 모델이 필요하지 않습니다.

## 처음 한 번 준비

1. 노트북에 USB 카메라를 연결하고 카메라·작업 배경을 고정합니다. 옮길 수 있는 스탠드가 있는지 선택합니다.
2. 프로그램이 보여 주는 준비 시험/본수집 수량을 확인하고 **이 계획으로 시작**을 누릅니다.
3. 카메라 후보 인덱스와 DSHOW 또는 MSMF, 요청 해상도를 선택하고 **연결**합니다. 후보0이 USB 카메라라는 뜻은 아닙니다.
   현재 장치는 영상으로 확인합니다. 다른 후보로 바꾸려면 먼저 **연결 해제**가 끝나야 합니다. 자동 탐색/폴백은 없습니다.
4. 실제 영상 크기를 확인합니다. 요청과 달라도 원본을 임의로 확대/축소하지 않습니다. FPS는 장치 보고값이며 실측 속도가 아닙니다.
5. 열린 케이스를 정상 상태로 화면 중앙에 놓습니다. **영상에서 기준 영역 지정**을 누르고 큰 영상에서 케이스 외곽을 드래그합니다.
   이동·회전 여유를 남겨야 합니다. 실물 L/R 표시를 보고 화면과의 대응을 선택합니다.
6. **이 구도로 기준 사진 시작**을 누릅니다. 정상 → 양쪽 빈자리 안내에 따라 각각 준비 버튼을 누릅니다.
   기준 사진 두 장에서 양쪽 자리 윤곽과 실물 L/R을 직접 확인하고 체크한 뒤 계속합니다.

카메라 높이·조도는 측정하지 않았다면 null로 남습니다. 화면 영역은 픽셀 비율이며 실제 mm나 물체 위치 라벨이 아닙니다.

## 이후에는 지금 할 일만 따라 하세요

- 노란 윤곽·중심·화살표에 맞춰 물체를 놓습니다. 카메라는 계속 고정합니다. 약 ±10°는 초기 목표이며 실제 각도 측정이 아닙니다.
- 조명 이동 안내가 나올 때만 조명을 옮깁니다. 작은 조명 그림은 배치 안내이며 광량 실측이 아닙니다.
- 안내대로 이어폰을 넣거나 뺀 뒤 손을 빼고 **준비됐어요**를 한 번 누릅니다. Space도 가능하며 누르고 있어도 연속 촬영하지 않습니다.
- 약 1.2초 후 새 프레임의 움직임이 잦아들면 한 장 저장합니다. 저장·재로드·해시 확인 후 다음 상태로 자동 진행합니다.
- 8초 안에 안정되지 않거나 카메라가 끊기면 촬영하지 않고 다시 준비하도록 안내합니다. **잠시 멈춤 / Esc**로 예약 촬영을 취소합니다.
- 선명도·밝기·반사·유사 사진 경고는 보조 지표입니다. 빈자리/어두운 조건은 지표가 다를 수 있습니다.
  경고를 확인하고 묶음 검토까지 유지하거나 보류 후 다시 찍습니다. 정지한 손이나 실제 L/R 상태를 자동 판별하지 않습니다.

정상·왼쪽 누락·오른쪽 누락·양쪽 누락이 모이면 비교 화면이 자동으로 열립니다.
사진을 누르면 확대됩니다. 모든 사진의 실제 상태·반사·흐림·손 가림·같은 배치 유지를 확인하고 체크한 뒤 **묶음 확인 완료 · 계속**을 누릅니다.
이때만 `human-batch-review-v1`의 사람 확정이 기록됩니다. 품질 경고 확인은 사람 확정과 다릅니다.

문제가 있는 사진만 **이 사진 다시 촬영**에 체크하고 이유를 선택합니다. 물체를 실제 다시 놓았으면 해당 체크도 합니다.
이전 PNG·거절 사유·재촬영 이력은 남습니다. 같은 상태에서 재배치 없이 다시 찍으면 같은 episode를 유지합니다.

## 계획과 수량

| 사용 가능한 조명 | 준비 시험 | 본수집 초기 계획 |
|---|---:|---:|
| 이동 가능한 스탠드 있음 | 중앙 × 3조명 × 4상태 = 12 | 4회차 × 3조명 × 5배치 × 4상태 = 240 |
| 방 조명만 사용 | 중앙 × 1조명 × 4상태 = 4 | 4회차 × 1조명 × 5배치 × 4상태 = 80 |

기준 사진 2장과 준비 시험은 본수집 수량에서 제외합니다. 처음 설정에서 사용할 수 없는 조명은 제외 이유와 조정된 목표를 저장합니다.
진행 중 **고급 설정 → 현재 조건 생략**은 목표를 줄이지 않고 미수집/사유로 남깁니다. **생략한 조건 다시 안내**로 돌아갈 수 있습니다.
준비 시험에 생략이 남으면 본수집으로 가지 않습니다. 모든 준비 사진을 사람이 확인한 뒤 상태별 선명도 보조 시작값을 한 번 보정하고 규칙 버전2로 고정합니다.

순서는 회차 → 조명 → 배치 → 상태입니다. 매번 사용자가 조건을 고르거나 ID·메모를 입력할 필요가 없습니다.
위치는 항상 최초 기준에서 계산하므로 왼쪽 이동·회전이 누적되지 않습니다. **수집 현황**에서 목표/저장/확정/검토 대기/보류/재촬영/미수집을 확인합니다.
240개의 파일이 있다는 이유로 완료하지 않습니다. 계획의 필수 단계가 사람 확정되어야 합니다. 240장은 충분한 학습 성능을 보장하는 숫자가 아닙니다.

## 여러 날 나눠 촬영하고 재개하기

다음 회차에서는 물체를 치웠다가 다시 배치합니다. 가능하면 다른 시간/날짜에 진행합니다.
B01/B02는 학습용 후보, B03은 검증용 후보, B04는 최종 시험용 예약입니다. 실제 데이터 분할은 아직 하지 않습니다.
연속 촬영은 같은 `origin_group_id`를 유지합니다. 같은 그룹을 다른 용도에 배정하면 진행을 차단합니다.
B03/B04를 준비할 때는 촬영을 중단한 뒤 별도 시간에 설치·배치를 새로 준비했는지 사람이 선언해야 합니다. 단순 앱 재시작이나 회차 이름 변경은 독립성의 증거가 아닙니다.
소프트웨어가 실제 환경 독립성을 입증한 것은 아니며 이후 데이터 검토가 필요합니다.

창을 닫고 다시 실행하면 **시작 / 이어하기 → 중단한 계획 이어하기**로 `C…` 폴더를 선택합니다.
원본/manifest/이벤트 해시를 검증한 뒤 저장 또는 검토 대기 위치로 돌아옵니다. 카메라 연결 후 이전과 같은 실제 구도인지 확인합니다.
준비 버튼을 눌렀던 상태는 복원하지 않습니다. 저장 후 UI 전진 전에 중단되어도 이미 저장된 사진을 다시 찍지 않습니다.
카메라·해상도·높이·구도가 바뀌었다면 새 기준 영역/사진을 만듭니다. 진행 중 묶음은 새 기준으로 다시 찍고 원래 자료는 보존합니다.

제품/계획을 바꿀 때는 고급 설정에서 제품을 선택해 새 계획을 만듭니다. 기존 계획을 덮어쓰지 않습니다.
같은 계획 ID의 내용 변경은 `plan_version`을 올려야 합니다. 앱 재시작 후 새 계획도 같은 저장 루트의 최근 검증된 계획에서 그룹 관계만 이어받으며 사진/완료 수량은 편입하지 않습니다.
다른 저장 루트나 외부에서 수동 복사한 자료의 물리적 독립성까지 자동 보장하지 않습니다.

## 저장과 오류 복구

기본 위치: `data/proxy/raw/collections/C…/`

| 파일/폴더 | 역할 |
|---|---|
| collection.json | v1 제품·지시·계획·사용 조명 사본과 SHA256, 기존 계획/그룹 연결 |
| collection-events.jsonl | v1 순서/이전 해시를 연결한 setup·준비·촬영 시도·거절·묶음 확인 이력 |
| sessions/S…/ | 기존 CollectionSession의 원본 PNG, manifest.jsonl v2, session-info.json v1 |
| exports/EXPORT…/ | 라벨링 인계 JSON 목록과 요약 |

같은 수집은 OS 파일 잠금으로 한 창만 수정합니다. 잠금 파일을 임의로 삭제하지 않습니다. 정상 종료/프로세스 종료 시 OS 잠금이 해제됩니다.
여러 파일을 하나의 원자적 transaction으로 저장하는 것은 아닙니다. 먼저 촬영 의도를 기록하고 기존 저장기로 PNG/manifest를 검증한 뒤 시도를 연결합니다.
완전한 PNG/manifest가 있고 마지막 연결 이벤트만 누락되면 재개 시 기존 기록으로 복원합니다.
orphan PNG, 손상된 manifest, 부분 이벤트 줄, 해시 불일치는 자동 삭제/보정하지 않습니다. 오류 경로를 보존하고 촬영을 멈춘 뒤 복사본에서 원인과 복구를 확인합니다.
오류를 숨기고 수량을 늘리지 않습니다. 저장 중 창을 닫으면 진행 중인 한 장의 기록 작업을 마친 뒤 닫습니다.

## 라벨링에 넘기기 / 엔진으로 재사용

**고급 설정 → 라벨링용 자료 정리**는 원본을 재검증하고 이미지 경로/SHA256, capture/step/attempt/session/episode/round/setup/origin_group, 상태, 조건, 제품·계획 버전을 JSON으로 내보냅니다.
사람 확정된 본수집만 `images_for_labeling.json`에 포함됩니다. 학습 후보·검증 후보·시험 예약은 별도 목록이며 시험 예약은 학습 목록에 포함되지 않습니다.
준비/기준·거절·검토 대기는 `excluded_or_pending.json`, 합성 입력은 `sample_only.json`으로 분리합니다. 원본은 변경하거나 삭제하지 않습니다.
시나리오/제거 목록은 촬영자의 정답 기록입니다. 이후 추론 코드가 이 값을 읽어 검사 결과를 결정하면 안 됩니다.
가짜 box, 빈 YOLO label, 모델 학습 결과를 만들지 않습니다. 다음 작업에서 사람이 부품 위치를 라벨링해야 합니다.

제품 교체 시 같은 폴더의 `profile.json`(부품/상태), `display.json`(표시 이름), `capture-guide.json`(각 목표 상태의 완전한 배치 지시), `collection-plan.json`(회차/조명/배치/품질 시작값)을 준비합니다.
지시는 이전 상태에만 의존하지 않고 재촬영에도 맞게 작성합니다. 부품·상태 개수가 다른 가상 제품으로 공통 흐름을 검증했으며 실제 엔진 성공으로 집계하지 않습니다.
계획 필드와 허용 범위는 `wizard_plan.validate_plan`이 검증합니다. 실제 엔진 부품·좌표·불량 이름은 엔진 실물과 승인된 요구가 생긴 뒤 정의합니다.

기존 수동/한 조건 도우미는 **고급 설정 → 기존 수동 / 한 조건 도우미** 또는 `--manual` 인자로 열 수 있습니다.
기존 v1/v2·사진별 검토 정책은 그대로이며 새 묶음 확인 정책과 혼동하지 않습니다.

직접 실행: `.venv\Scripts\python.exe -X utf8 -m training.capture_windows`

자동 테스트: `.venv\Scripts\python.exe -m unittest discover -s tests -v`

개발용 합성 화면: `.venv\Scripts\python.exe tests\wizard_visual_smoke.py --review`
이 테스트는 `runs/`에만 sample을 저장하고 실제 카메라를 열지 않습니다.
